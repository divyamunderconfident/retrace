## Method

- Agent: the demo research agent on groq/openai/gpt-oss-20b, temperature 0. Each mutation patches the agent (see `MUTATIONS` in the script); the mutated step is logged by the mutation itself when it first changes an input or output, independently of the diff.
- A: `diff(correct, broken)` first divergence compared with the mutated step.
- B: the analyst model gets the same instructions plus either both runs' JSON logs or the diff report, and must reply with a step index and one of the 5 bug types. Scored by exact match, no partial credit.

## Limitations

- 10 mutations and one trial each: the numbers are indicative, not statistically meaningful.
- Steps before the mutation are identical by construction: model calls with the same input come from llm.py's cache. Without the cache, a live model at temperature 0 can still vary between runs and create divergences unrelated to the bug.
- Mutations that change the system prompt or a tool description take effect at step 0, so locating them is easy; the harder cases are the tool and context mutations.
- The demo runs are short (a few steps), so the raw logs are small enough for the analyst to read whole. The PRD's premise is long runs, where raw logs are a wall of JSON; this experiment does not test that.
- One analyst model, one prompt.
